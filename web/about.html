PURPOSE · PROCESS · IMPLEMENTATION

An inspectable interoperability experiment.

Created to explore compatibility with third-party optical inserts and lenses for Apple Vision Pro. Enter supported optical values, see how they are represented, and export a circular code.

01 / GENERATION

From lens values to five rings

  1. Validate the optics

    Sphere and cylinder must match a finite table in 0.25 D steps. Positive-cylinder input is transposed into the table’s non-positive notation. Canonical axes use a 4° grid; rounding is reported, or rejected in exact mode. Unsupported optical pairs are rejected.

  2. Build a 128-bit payload

    Version 5 records both eyes, axis identifiers, explicit VR adds, lens type, and an 80-bit synthetic identity. Web Crypto creates fresh identity bytes. These bytes vary the symbol; they do not create manufacturer records.

  3. Protect and place the bits

    A reversible transformation produces 138 message bits. Separate gap and color blocks receive polynomial checksums and Reed–Solomon parity. Fixed position tables place the gap block and metadata into 128 slots across five rings.

  4. Order the arcs

    Gap bits join slots into visible components. The encoder chooses an inversion with enough components, then uses fixed priority and neighbor tables to order 66 components for color data. Remaining components repeat gap information in the specified wrap-aware order.

  5. Validate and export

    The engine checks the payload round trip, checksums, parity, and redundant colors, then renders an SVG. PNG and JSON exports are also available. If a topology fails, random mode tries up to 64 identities while keeping the optics unchanged.

Calibration adjustments are shown separately from the encoded inputs. They can include transformations and clamping; missing calibration limits are reported as unavailable. These values do not establish factory calibration.

02 / LOCAL PROCESSING

Generation stays in your browser

The static page loads a Rust engine compiled to WebAssembly. There is no server-side generation, analytics, or external service call. Optical values and synthetic identities are not uploaded or saved to browser storage. Downloaded files contain the output you choose to export; the JSON report includes the request and identity.

03 / IMPLEMENTATION

A standalone Rust encoder

The browser runs the encoder as WebAssembly. The GPUI desktop application uses the same Rust library directly. Numeric format tables are embedded at build time; generation needs no manufacturer service.

04 / SCOPE

What the checks establish

The checks verify in-memory symbol bits. Development also included synthetic test cases and separate raster comparisons. These results do not establish camera recognition, headset enrollment, authenticity, factory records, or clinical suitability. The tool has no camera scanner.
